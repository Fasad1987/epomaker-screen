# RT82 Screen — экран Epomaker RT82 в Linux без браузера

Приложение для KDE Plasma и консольная утилита для клавиатуры **Epomaker RT82**:

* **время на экране клавиатуры** ставится само: при подключении, после сна и раз в несколько часов;
* **свои картинки и GIF** (до 3 экранов) загружаются без Epomaker Hub;
* **виджеты на экране**: часы, дата, CPU/RAM/температура/сеть (текст, полоса, график), «сейчас играет» (MPRIS),
  погода (Open-Meteo, без ключа), вывод любой команды, картинки, плашки, прогресс дня. Их можно расставлять мышью
  в редакторе, а **живой режим** обновляет их на клавиатуре постоянно;
* **ввод пароля шифрованного диска с RT82** на этапе initrd (скрипт для ALT/make-initrd, dracut,
  initramfs-tools) и советы для меню GRUB;
* udev-правило, после которого клавиатуру видит и **Epomaker Hub в Chromium**.

> ⚠️ **Код не проверялся на настоящей RT82** — у автора её нет. Протокол экрана взят из двух открытых проектов,
> которые работают с RT82 и с QK108 (тот же контроллер экрана, см. ниже), и проверен на эмуляторе контроллера
> в `tests/`. Начните с безопасных команд (`rt82ctl list`, `rt82ctl sync-time`), потом пробуйте загрузку
> картинки и только потом — живой режим. Если что-то пошло не так — см. [«Если экран завис»](#если-экран-завис).

| [wyattades/keyscreen](https://github.com/wyattades/keyscreen) (TypeScript/Bun) | «живой» экран, часы, системный монитор на **QK108**; RT82 указана как «вероятно совместима» | другой ID клавиатуры, интерфейс в браузере (localhost), GNOME-расширение вместо KDE |

Здесь — собственная реализация протокола (MIT) по описаниям из первых двух проектов: свой кодировщик QGIF на
чистом Python, без wasm, Node.js и браузера.

## Установка

Нужны Python 3.9+ и PyQt6 (или PySide6):

```bash
# ALT Linux (sudo там по умолчанию нет — команды от root выполняются через su -c)
su -c 'apt-get install python3-module-PyQt6'
# Fedora
sudo dnf install python3-pyqt6
```

Необязательно: `playerctl` — для виджета «Сейчас играет» (без него используется `gdbus`).

```bash
git clone https://github.com/fasad1987/epomaker-rt82-plasma.git
cd epomaker-rt82-plasma
scripts/install.sh
```

Скрипт ставит программу в `~/.local`, добавляет «Экран RT82» в меню и в автозапуск (в трей). Права root
нужны только для udev-правила: скрипт попросит пароль через `sudo`, а если sudo нет или вам он не разрешён
(как в ALT Linux по умолчанию) — через `su` (пароль root).

Можно и сразу запустить установщик от root — например, в ALT:

```bash
su -c 'scripts/install.sh'
```

Тогда udev-правило ставится сразу, а программа — для того пользователя, который вызвал `su` (или `sudo`).
Если скрипт не сможет его определить, укажите явно: `su -c 'scripts/install.sh --user ИМЯ'`. Пишите `su -c`, а
не `su -`: со `su -` текущий каталог сменится на `/root`, и путь `scripts/install.sh` не найдётся (тогда
указывайте полный путь к скрипту). Каталог проекта должен быть доступен этому пользователю на чтение.

После установки **переподключите клавиатуру кабелем** и проверьте:

```bash
rt82ctl list
```

В выводе должно быть `доступ=да` у интерфейса `usage_page=0xFF60`.

Вместо приложения в трее можно поставить только фоновую синхронизацию времени (служба systemd --user):
`scripts/install.sh --service`. Удаление: `scripts/uninstall.sh` (или `su -c 'scripts/uninstall.sh'`).

## Экран клавиатуры работает только по кабелю

Экраном управляет отдельный контроллер (USB `1919:1919`), который сидит за USB-хабом внутри клавиатуры и
появляется только по запросу. По Bluetooth и 2,4 ГГц он недоступен — так же и у официальной программы.

## Приложение «Экран RT82»

* **Редактор**: слева превью экрана 240×135 в масштабе 3:1. Щёлкните виджет — выбрать; тащите — переместить;
  за правый нижний угол — изменить размер; стрелки — сдвиг на 1 px, Shift+стрелки — размер, Delete — удалить.
  Справа — список виджетов (верхний рисуется поверх) и их свойства. Раскладка сохраняется автоматически в
  `~/.config/rt82-plasma/layout.json`.
* **Живой режим** — виджеты обновляются на клавиатуре постоянно. При включении экран на пару секунд покажет
  «Downloading», дальше — без него. Правки в редакторе сразу видны на клавиатуре.
* **Отправить снимок** — отрисовать раскладку один раз и сохранить картинкой (часы при этом «застынут»: для
  меняющихся данных нужен живой режим; встроенные часы клавиатуры всегда идут и так).
* **GIF/картинки…** — загрузить до 3 файлов (GIF, PNG, JPEG, WebP, `.qgif`).
* **Время** — синхронизировать часы клавиатуры сейчас.
* **Пауза** — отпустить клавиатуру, например чтобы открыть Epomaker Hub. Контроллер экрана принимает только
  одну программу: если две пишут в него одновременно, он может зависнуть.

На клавиатуре: **Fn + правый Shift** — страница GIF (на ней показываются виджеты и картинки), **Fn + Enter** —
переключение страниц экрана (часы, батарея и т. д.).

### Как работает живой режим

Экран умеет только проигрывать анимацию из своей flash-памяти, команды «нарисовать кадр» нет. Поэтому
программа пишет во flash «бесконечную» анимацию и дописывает кадры на несколько секунд вперёд — экран читает
их по мере проигрывания. Кадры рисуются на то время, когда они окажутся на экране, поэтому часы не отстают.

* По умолчанию 1 кадр в секунду. Неизменившийся кадр занимает 255 байт, изменившийся — только изменённые
  плитки 4×4.
* Каждые 5 минут начинается новый поток (переключение ~0,15 с, без «Downloading»): экран проигрывает чуть
  медленнее заявленного, и так отставание не накапливается.
* Примерно раз в час область flash (24 блока по 64 КБ) стирается; на эти ~4 секунды на экране показывается фон
  раскладки без данных. Это ~9 000 циклов стирания в год — заметно меньше ресурса SPI-flash (~100 000), но
  если живой режим вам не нужен постоянно, выключайте его. При 2 к/с износ вдвое больше.
* Параметры — в «Файл → Настройки».

## Консоль: `rt82ctl`

```bash
rt82ctl list                       # интерфейсы RT82 и права доступа
rt82ctl sync-time                  # поставить время
rt82ctl info                       # размер экрана и тип подключения
rt82ctl upload cat.gif             # до 3 файлов: GIF/PNG/JPEG/WebP/.qgif
rt82ctl upload a.png b.gif --fit cover
rt82ctl preview out.png            # нарисовать раскладку в PNG
rt82ctl layout                     # один раз отрисовать раскладку и загрузить картинкой
rt82ctl live                       # живой режим в терминале (Ctrl+C)
rt82ctl watch                      # фоновая синхронизация времени (то же, что служба rt82-watch)
```

Раскладку можно взять из другого файла: `--file my-layout.json`.

## Ввод пароля при загрузке

Это две разные ступени, и чинятся они по-разному.

### 1. Пароль зашифрованного раздела (initrd)

Здесь клавиатуру обслуживает уже ядро Linux, но только теми драйверами, что попали в образ initrd. В ALT Linux
образ собирает make-initrd, и драйверы клавиатуры он подбирает по клавиатурам, подключённым в момент сборки
(и помечает их как модули для аварийной консоли). Вероятная причина: при сборке образа RT82 была подключена по
радио или не была подключена, и драйверов её цепочки (`usbhid`, `hid-generic`, контроллер USB) в образе нет или
они не загружаются вовремя. В Fedora initrd собирает dracut по другим правилам, поэтому там ввод работает.
Точно это покажет `su -c 'boot/rt82-boot-keyboard.sh --check'`.

Подключите RT82 кабелем и выполните от root:

```bash
su -c 'boot/rt82-boot-keyboard.sh'
```

(или `sudo boot/rt82-boot-keyboard.sh`, где есть sudo).

Скрипт:

* по sysfs находит драйверы всей цепочки от клавиатуры до USB-контроллера;
* показывает, каких из них нет в текущем initrd;
* после подтверждения добавляет их между метками в `/etc/initrd.mk` (резервная копия рядом) — для ALT,
  либо в `/etc/dracut.conf.d/90-rt82-keyboard.conf`, либо в `/etc/initramfs-tools/modules`;
* `usbhid` и `hid_generic` загружаются в initrd ещё до udev (`MODULES_PRELOAD`);
* пересобирает initrd для текущего ядра.

Проверить без изменений: `su -c 'boot/rt82-boot-keyboard.sh --check'`. Откатить: `--undo`.

### 2. Меню и пароль GRUB

GRUB работает до Linux. На UEFI клавиатуру в нём обслуживает **прошивка компьютера**, а не драйверы Linux,
поэтому программой это не исправить. Что помогает:

1. Подключить RT82 кабелем напрямую в порт на материнской плате сзади (лучше USB 2.0), без хабов и передней
   панели.
2. В настройках UEFI выключить **Fast Boot** (быстрая загрузка часто пропускает инициализацию USB), включить
   **USB Legacy Support / USB Keyboard Support** и **XHCI Hand-off**.
3. Проверить, печатает ли клавиатура в меню самой прошивки (Del/F2). Если нет — прошивка не справляется с
   этой клавиатурой (у RT82 внутри USB-хаб). Тогда для этого шага — донгл 2,4 ГГц или другая клавиатура.
4. Если в `/etc/sysconfig/grub2` (ALT) или `/etc/default/grub` задано `GRUB_TERMINAL_INPUT` с `usb_keyboard`
   или `at_keyboard`, на UEFI верните `console` и выполните `update-grub`. Скрипт выше подскажет, если это так.

Если не помогло, соберите диагностику и пришлите файл:

```bash
su -c 'boot/diagnose.sh'
```

## Epomaker Hub в Chromium («RT82-m2-v36b0-p30a3-…»)

Chromium перечисляет HID-устройства через udev и поэтому «видит» клавиатуру, но открыть `/dev/hidrawN` без
прав не может — и Hub показывает ошибку. Это подтверждается в `chrome://device-log`: там будет
`Failed to open '/dev/hidrawN': FILE_ERROR_ACCESS_DENIED`. udev-правило из этого проекта
(`udev/70-epomaker-rt82.rules`, ставится `scripts/install.sh`) даёт права пользователю за компьютером только на
служебные интерфейсы клавиатуры и контроллера экрана; обычные интерфейсы ввода остаются root-only, так что
программы не смогут читать нажатия.

После установки правила переподключите клавиатуру и перезапустите Chromium. Если Chromium установлен из Flatpak
или Snap, ему дополнительно нужен доступ к устройствам (`flatpak override --user --device=all
org.chromium.Chromium`). Перед работой в Hub нажмите **Пауза** в «Экране RT82».

Если ошибка не уйдёт, пришлите строку из `chrome://device-log` и вывод `rt82ctl list`.

## Если экран завис

Контроллер экрана может перестать отвечать, если с ним одновременно работают две программы (например, Hub в
браузере и живой режим) или при неудачном стирании. По опыту keyscreen, помогает только полное выключение:
отключите кабель, **выключите клавиатуру переключателем питания** (у неё есть аккумулятор), подождите ~10 с и
включите снова. Клавиатура как устройство ввода при этом работает.

## Устройство проекта

```
rt82/hidraw.py     поиск /dev/hidraw* через sysfs, разбор HID-дескриптора, ввод-вывод
rt82/protocol.py   ID, команды, пакеты, таблица слотов, формат времени
rt82/device.py     клавиатура (36b0:30a3) и контроллер экрана (1919:1919): время, загрузка, стирание
rt82/qgif.py       кодировщик/декодер QGIF (плитки 4×4, 2 цвета RGB565 + 2 промежуточных)
rt82/live.py       живой режим: потоковая запись кадров, сегменты, стирание
rt82/service.py    фоновый поток: подключение, синхронизация времени, живой режим, задания
rt82/widgets.py    виджеты и отрисовка раскладки (QPainter)
rt82/data.py       данные: /proc, hwmon, MPRIS, Open-Meteo, команды
rt82/gui.py        приложение для Plasma: редактор, трей
rt82/cli.py        rt82ctl
udev/              udev-правило
boot/              ввод пароля в initrd, диагностика
tests/             тесты и эмулятор контроллера экрана
```

Протокол кратко: клавиатуре `36b0:30a3` (интерфейс 1, usage page `0xFF60`) отправляется `AA E0` — через ~1,5 с
появляется контроллер `1919:1919` (64-байтные отчёты `AA cmd addr[3] len 00 00 data[56]`). Время —
`10`, `17` с цифрами `ГГГГ ММ Д(нед) ДД чч мм сс`, `11`. Картинки хранятся во flash блоками по 64 КБ в формате
QGIF, экран проигрывает слот 1 таблицы слотов. Подробные описания — в
[PROTOCOL.md у keyscreen](https://github.com/wyattades/keyscreen/blob/main/PROTOCOL.md) и
[PROTOCOL.md у rt82display](https://github.com/guysoft/rt82display/blob/main/PROTOCOL.md).

Тесты:

```bash
python3 -m pytest          # нужны pytest и PyQt6/PySide6 (тесты отрисовки пропускаются без Qt)
```

Эмулятор в `tests/fake_screen.py` проверяет, что программа не пишет в нестёртую flash, не стирает
проигрываемую картинку, укладывает стирание в безопасное время и что экран ни разу не читает недописанный кадр
(3 часа живого режима, замедленное воспроизведение, выход из сна).
